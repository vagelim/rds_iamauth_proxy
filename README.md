# rds-iamauth-proxy

A local proxy that lets you connect **PostgreSQL and MySQL clients** to AWS RDS
instances using IAM authentication — no password management required.

The proxy handles the IAM token generation and TLS negotiation transparently.
Your client connects to `localhost` with no password (or any dummy password);
the proxy authenticates to RDS with a short-lived presigned token.

## Prerequisites

- [Rust](https://rustup.rs/) (to build from source) or a pre-built binary
- [AWS CLI v2](https://docs.aws.amazon.com/cli/latest/userguide/install-cliv2.html)
- [Session Manager plugin](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager-working-with-install-plugin.html) (if connecting via SSM tunnel instead of direct VPC access)
- An IAM user/role with `rds-db:connect` permission and an RDS database user
  configured with `AWSAuthenticationPlugin` (MySQL) or `rds_iam` role (PostgreSQL)

## Install

```sh
cargo install rds_proxy
```

Or build from source:

```sh
git clone https://github.com/goldfiglabs/rds_iamauth_proxy
cd rds_iamauth_proxy
cargo build --release
# binary at: ./target/release/rds_proxy
```

## Quick Start

### 1. Create a config file

**PostgreSQL** (`pg-proxy.json`):
```json
{
  "endpoint": {
    "hostname": "my-instance.abcdef.us-east-1.rds.amazonaws.com",
    "port": 5432
  },
  "region": "us-east-1"
}
```

**MySQL** (`mysql-proxy.json`):
```json
{
  "endpoint": {
    "hostname": "my-instance.abcdef.us-east-1.rds.amazonaws.com",
    "port": 3306
  },
  "region": "us-east-1",
  "db_type": "mysql"
}
```

### 2. Start the proxy

```sh
# PostgreSQL — listens on 127.0.0.1:5435 by default
AWS_PROFILE=my-profile rds_proxy --config pg-proxy.json

# MySQL — listens on 127.0.0.1:3435 by default
AWS_PROFILE=my-profile rds_proxy --config mysql-proxy.json
```

### 3. Connect your client

**PostgreSQL:**
```sh
psql -h 127.0.0.1 -p 5435 -U iamdb -d mydb
# password prompt: leave empty or enter anything
```

**MySQL:**
```sh
mysql -h 127.0.0.1 -P 3435 -u iamdb --enable-cleartext-plugin mydb
# no password needed — the proxy handles it
```

> **MySQL note:** `--enable-cleartext-plugin` is required. The proxy advertises
> `mysql_clear_password` so your client sends the password field in cleartext
> over the (localhost) connection. The actual IAM token is generated by the
> proxy and sent over the TLS-encrypted proxy-to-RDS leg.

## Connecting via SSM Tunnel

When your RDS instance isn't directly reachable from your machine (e.g. in a
private subnet), use an AWS SSM port-forwarding tunnel through a bastion host.

**Step 1: Start the SSM tunnel**

```sh
# For MySQL (port 3306)
aws ssm start-session \
  --target <bastion-instance-id> \
  --document-name AWS-StartPortForwardingSessionToRemoteHost \
  --parameters '{
    "host": ["my-instance.abcdef.us-east-1.rds.amazonaws.com"],
    "portNumber": ["3306"],
    "localPortNumber": ["3306"]
  }'

# For PostgreSQL (port 5432)
aws ssm start-session \
  --target <bastion-instance-id> \
  --document-name AWS-StartPortForwardingSessionToRemoteHost \
  --parameters '{
    "host": ["my-instance.abcdef.us-east-1.rds.amazonaws.com"],
    "portNumber": ["5432"],
    "localPortNumber": ["5432"]
  }'
```

Keep this running in a separate terminal.

**Step 2: Configure the proxy to connect through the tunnel**

Add `proxy_endpoint` and `danger_accept_invalid_certs` to your config:

```json
{
  "endpoint": {
    "hostname": "my-instance.abcdef.us-east-1.rds.amazonaws.com",
    "port": 3306
  },
  "region": "us-east-1",
  "db_type": "mysql",
  "proxy_endpoint": {
    "hostname": "127.0.0.1",
    "port": 3306
  },
  "danger_accept_invalid_certs": true
}
```

- `proxy_endpoint` — the local address the proxy connects to (the SSM tunnel).
  `endpoint` is still set to the real RDS hostname because the proxy uses it
  for IAM token generation and TLS SNI.
- `danger_accept_invalid_certs` — required because the RDS certificate's
  hostname won't match `127.0.0.1`. This only affects the proxy-to-RDS TLS
  connection; it is safe to use when going through a localhost SSM tunnel.

**Step 3: Start the proxy and connect**

```sh
AWS_PROFILE=my-profile rds_proxy --config my-config.json

# Then in another terminal:
mysql -h 127.0.0.1 -P 3435 -u iamdb --enable-cleartext-plugin mydb
```

## Config Reference

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `endpoint.hostname` | string | **required** | RDS instance hostname |
| `endpoint.port` | number | **required** | RDS port (5432 for PG, 3306 for MySQL) |
| `region` | string | **required** | AWS region (e.g. `us-east-2`) |
| `db_type` | string | `"postgres"` | `"postgres"` or `"mysql"` |
| `proxy_endpoint.hostname` | string | — | Connect here instead of endpoint (for SSM tunnels) |
| `proxy_endpoint.port` | number | — | Port for proxy_endpoint |
| `ca_bundle` | string | — | Path to custom CA bundle PEM file (defaults to embedded RDS global bundle) |
| `danger_accept_invalid_certs` | bool | `false` | Skip TLS cert validation — only use with localhost SSM tunnels |
| `local_password` | string | — | Password clients must provide to connect through the proxy (see below) |

## Default Listen Ports

| db_type | Default listen address |
|---------|------------------------|
| postgres | `127.0.0.1:5435` |
| mysql | `127.0.0.1:3435` |

Override with `--listen`:
```sh
rds_proxy --config my-config.json --listen 127.0.0.1:9999
```

## Local Password Protection

By default, anyone who can reach the proxy's listen port can connect through it
to your RDS instance. Set `local_password` in your config to require clients to
authenticate before the proxy will forward the connection:

```json
{
  "endpoint": { "hostname": "...", "port": 3306 },
  "region": "us-east-2",
  "db_type": "mysql",
  "local_password": "my-secret-password"
}
```

Clients then provide this password when connecting:

**MySQL:**
```sh
mysql -h 127.0.0.1 -P 3435 -u iamdb -p'my-secret-password' --enable-cleartext-plugin mydb
```

**PostgreSQL:**
```sh
PGPASSWORD=my-secret-password psql -h 127.0.0.1 -p 5435 -U iamdb -d mydb
```

This password is only used for the local client-to-proxy connection. The
proxy still authenticates to RDS using a separate IAM token.

## Setting Up an IAM Database User

The RDS instance needs a database user configured for IAM auth. The proxy
generates the token; you need to create the user once.

**PostgreSQL:**
```sql
CREATE USER iamdb WITH LOGIN;
GRANT rds_iam TO iamdb;
GRANT CONNECT ON DATABASE mydb TO iamdb;
```

**MySQL:**
```sql
CREATE USER 'iamdb'@'%' IDENTIFIED WITH AWSAuthenticationPlugin AS 'RDS';
GRANT ALL ON mydb.* TO 'iamdb'@'%';
```

The IAM role or user running the proxy also needs an IAM policy allowing
`rds-db:connect`:
```json
{
  "Effect": "Allow",
  "Action": "rds-db:connect",
  "Resource": "arn:aws:rds-db:<region>:<account>:dbuser:<db-resource-id>/iamdb"
}
```

## Development

Build and run locally:
```sh
cargo build
AWS_PROFILE=my-profile ./target/debug/rds_proxy --config my-config.json
```

Build the Docker image:
```sh
docker build -t rds_proxy:test .
```

Run via Docker (mounts `~/.aws` and `~/.rds_proxy/config.json`):
```sh
AWS_PROFILE=my-profile ./run_docker.sh
```
